## 第1回：最小構成とSSM方針 〜SSHが使えない環境から始まった〜
📅 〜2026-07-28 頃

**この回のテーマ**
Terraform で最初の VPC・サブネット・EC2 をコードで作成。`init → plan → apply` の基本サイクルを体験。

**つまずき**
自宅Wi-Fiがアウトバウンド **22番（SSH）をブロック**していて、そもそもSSH接続ができなかった。

**腑に落ちた瞬間**
制約を逆手に取り、最初から **SSM（Session Manager）** 前提で設計。SSMはEC2→AWSのアウトバウンド通信なので、インバウンドを一切開けずに運用できる。

**面接で使える一言**
「SSHが使えない環境だったので、最初からSSM前提で設計した。受信ポートを開けない運用ができる。」

**🔑 深掘り用キーワード**
SSM = アウトバウンド / Session Manager Plugin / inbound 0 で接続

## 第2回：変数化 〜ハードコードをやめる〜
📅 2026-07-29

**この回のテーマ**
`variables.tf` に `instance_type` / `region` / `vpc_cidr_block` / `subnets` / `project_name` を切り出し。共通タグは `locals` + provider の `default_tags` で一括付与。

**つまずき**
`locals` と `merge()` を**同時に**説明されて詰まった。ここで「1回に新概念は1つまで」という進め方が定着した。

**腑に落ちた瞬間**
`default` は「固定値」ではなく **「未指定時のフォールバック」＝省略を許すかの設計判断**。そして **variable=利用者が決める入力 / data=AWSが決める事実 / locals=コードが作る中間値 / resource=作るもの**、という「値の決定権は誰が持つか」の軸。

**面接で使える一言**
「タグは `default_tags` で共通化し、各リソースは `Name` だけ持たせた。管理タグを一箇所で変えられる。」

**🔑 深掘り用キーワード**
default=フォールバック / 変数の優先順位（-var > tfvars > TF_VAR_ > default）/ 補間 `"${}"` / default に変数不可→locals

## 第3回：for_each で複数AZ 〜count との違い〜
📅 2026-07-29

**この回のテーマ**
サブネットと route table association を `for_each = var.subnets` で複数AZ化。`apply` で13リソース作成。

**つまずき**
`validate` も `plan` も通るのに間違っているケースを5回体験（存在しないAZ名、CIDR重複、タグtypo…）。特に **このアカウントに `ap-northeast-1b` は存在しない**（a・c・d のみ）。

**腑に落ちた瞬間**
`count` はインデックス管理で真ん中挿入が破壊的。`for_each` はキー管理で安全。サブネット追加が **2 to add / 0 destroy** になることを実機で確認し、インデックスずれ回避を実証できた。

**面接で使える一言**
「将来のAZ追加に強くするため `count` ではなく `for_each` を選んだ。既存を壊さず要素を足せる。」

**🔑 深掘り用キーワード**
count=インデックス / for_each=キー / `[count.index]`単数・`[*]`リスト / 「validate通過≠正しい」

## 第4回：network モジュール化 〜moved で無停止リファクタ〜
📅 2026-07-30

**この回のテーマ**
`modules/network/` を作り、ルートに `module "network"` を配線。

**つまずき**
ルートとモジュールの役割を**逆に理解**していた（provider をモジュール側に置く等）。「意味がわからない」と申告し、作業を**6ステップに細分化**して突破。途中 **Ctrl+S 忘れ**で前日のコードが消えていた（→ git導入の伏線）。

**腑に落ちた瞬間**
**モジュール = 関数 / variables = 引数 / outputs = return / `module`ブロック = 呼び出し。** そして `moved` の実演で「**`plan` の数字はアドレス変更数ではなく依存グラフ上の波及範囲**」だと理解（9 destroy = 直接7 + 連鎖2）。`moved` は state の名札の付け替え。

**面接で使える一言**
「モジュール化してもAWS上のリソースは不変。stateのアドレス差分は `moved` で吸収し、`0 to destroy` で無停止移行した。」

**🔑 深掘り用キーワード**
モジュール=関数 / moved=名札付け替え / planは波及範囲 / init=プロバイダDL / 全角スペースで Invalid character / for式

## 第5回：compute モジュール化 〜名前の一意性と鍵の正体〜
📅 2026-07-31

**この回のテーマ**
`modules/compute/` に EC2・SG・IAM 一式をまとめ、外部参照を全部 `var.` 化。`apply` で成功、Outputs 表示。

**つまずき**
固定名がAWSの一意性制約に触れる箇所を整理（IAM=アカウント単位 / key_pair=リージョン単位 / SG=VPC単位）。一方 EC2 の Name タグは単なるラベルなので固定でOK、の区別。

**腑に落ちた瞬間**
秘密鍵はAWSに渡らず、`aws_key_pair` は**公開鍵だけ**アップロードする。鍵の対応は**ファイル名ではなく中身（数学的な対）**で決まる。出力は `module → root → 画面` の2段リレー。

**面接で使える一言**
「環境ごとに変わる値を全部変数化した。`module` を複数回呼ぶか `for_each` を付けるかで同構成を複製できる。」

**🔑 深掘り用キーワード**
名前の一意性（IAM/key_pair/SG）/ Nameタグ=ラベル / 公開鍵のみアップロード / 出力2段リレー

## 第6回：git 導入 〜何を追跡し、何を除外するか〜
📅 2026-07-31

**この回のテーマ**
`git init` → `.gitignore`（秘密鍵 / tfstate / `.terraform/`）→ 初回コミット。一枚岩構成は `docs/` に学習用退避。

**つまずき**
`.gitignore` に何を入れるかの判断基準が最初あいまいだった。

**腑に落ちた瞬間**
判断は**2軸**。🔴セキュリティ（秘密鍵の漏洩 / tfstateは平文機密＋**チームで機械マージ不能**）と 🟡衛生（`.terraform/` は再生成可・巨大 / `.bak` はノイズ）。`.gitignore` は追跡前に書く＝過去コミットは消せない。

**面接で使える一言**
「tfstateは秘密情報を含み、かつチームで機械マージできないため git から除外した。共有が必要なstateはこの後S3に載せた。」

**🔑 深掘り用キーワード**
gitignore 2軸 / tfstateは機械マージ不能 / `.terraform.lock.hcl` はコミット / stateは追跡ゼロなら削除安全

## 第7回：S3バックエンド化 〜stateをクラウドで共有する〜
📅 2026-08-03

**この回のテーマ**
ローカルにあった state を S3 へ移し、チームでの共有とロックの基盤を作る。

**つまずき**
IAMポリシーのJSONが書けずに前回はここで中断。しかも最初、書いたポリシーを**バケットポリシー欄に貼ってエラー**（`Principal` が必要と怒られた）。

**腑に落ちた瞬間**
IAMポリシー＝「**誰が**何をできるか」、バケットポリシー＝「このリソースに**誰が**触れるか」。`Principal` の有無が2つを分ける——ロールの権限ポリシー／信頼ポリシーと同じ対応だと気づいた。

**面接で使える一言**
「apply後にstateがS3に書かれること（ローカルは更新されないこと）を実データで確認。`use_lockfile` で同時apply事故も防いだ。」

**🔑 深掘り用キーワード**
卵と鶏 / ARN6欄 / init=接続・apply=書込み / serial・lineage / encryptは「前提」でなく「対策」 / ssm_sgリネーム・キーペア削除（不要コードは削除しgitが履歴保持）
